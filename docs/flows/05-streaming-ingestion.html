Ingestion

Streaming ingestion (REST)

One transaction at a time from the bank, accepted exactly once per Idempotency-Key and stored together with its outbox event.

Service ingestion-service :8083Endpoint POST /api/v1/transactionsSchema ingestion_db

            DB-->>S: COMMIT

            S-->>C: 202 Accepted

    end

Step by step

  1. TransactionController.ingestTransaction() (mapped to "" and /ingest) requires the Idempotency-Key header (max 128 chars) and validates TransactionRequest.
  2. TransactionIngestionServiceImpl.ingestTransaction() claims the key with setIfAbsent(key, "PROCESSING", 24h).
  3. If the key already exists: a transaction id as its value means a replay, so the service returns 200 with header Idempotent-Replayed: true; the value PROCESSING means 409.
  4. TransactionFactory.build() checks both accounts, source ≠ destination, amount > 0, and that the timestamp is no more than 60 s in the future. It then converts to INR and builds the Transaction and TransactionIngestedEvent/OutboxEvent.
  5. Any InvalidTransactionException deletes the key, so the client can correct the request and retry with the same key, and becomes a 422 via IngestionExceptionHandler.
  6. A TransactionSynchronization.afterCompletion hook is registered: on COMMIT it stores the transaction id under the key; on ROLLBACK it deletes the key.
  7. TransactionPersister.persistAll() persists both rows; Spring commits the transaction and the client receives 202 with the transaction id.
