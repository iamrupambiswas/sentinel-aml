One round trip; Redis runs the script atomically, so concurrent consumers cannot interleave add / trim / read.

CTR_THRESHOLD

Single large transaction (P6)

flowchart LR
    A["ctx.amountInr()"] --> B{">= threshold_amount
830000"}
    B -->|no| N["no hit"]
    B -->|yes| H["hit: evidence = [txnId]
bucket = txn date (UTC)"]
Stateless. The comparison uses the INR amount, so USD 10,000 (₹8,35,000) fires and so does ₹12,00,000 in cash.

STRUCTURING

Repeated deposits just below the reporting limit (P7)

flowchart LR
    A["amountInr"] --> B{"in [minAmountInr, maxAmountInr]?"}
    B -->|no| N["no hit, window untouched"]
    B -->|yes| W["addAndGet aml:win:struct:{acct}
window 1440 min"]
    W --> C{"count >= threshold (3)?"}
    C -->|no| N2["no hit"]
    C -->|yes| H["hit: evidence = all window txn ids
explanation includes time span"]
Only near-threshold amounts enter the window, so ordinary transactions never count.

RAPID_MOVEMENT

Money in and straight back out (P8)

flowchart LR
    D{"direction"} -->|CREDIT| C1["addAndGet aml:win:cr:{acct}
read aml:win:dr:{acct}"] --> RD
    D -->|DEBIT| D1["addAndGet aml:win:dr:{acct}
read aml:win:cr:{acct}"]
    D1 --> RD["for each anchor debit d in [ts, ts+window], latest first:
credits and debits in [d-window, d]"]
    RD --> M{"credits >= minCreditInr?"}
    M -->|no| N2["no hit"]
    M -->|yes| P{"debits x 100 >= 80 x credits?"}
    P -->|no| N3["no hit"]
    P -->|yes| H["hit: evidence = credit + debit ids"]
The percentage is compared exactly; it is rounded only for display, so 79.9999 % does not fire.

HIGH_RISK_JURISDICTION

Listed country or sanctioned name (P9)

flowchart LR
    C["counterpartyCountry"] --> CS{"WatchlistService.isHighRiskCountry"}
    N["counterpartyName"] --> NM["normalize: strip accents and punctuation, uppercase"]
    NM --> JW{"Jaro-Winkler >= nameSimilarity 0.92"}
    CS -->|yes| H["hit"]
    JW -->|yes| H
    CS -->|no| X{"both no?"}
    JW -->|no| X
    X --> NO["no hit"]
Fires on any amount. Matching is in memory against the cached watchlist.

BEHAVIORAL_DEVIATION

Sudden jump over the account's normal (P10)

flowchart LR
    T["txn"] --> H1["HSET aml:day:{acct}:{yyyyMMdd} txnId amountInr
TTL 95 days"]
    H1 --> S["today = sum of the day's values"]
    S --> B{"aml:baseline:{acct} exists?"}
    B -->|no| N["no hit"]
    B -->|yes| M{"today >= minDailyInr and
today > 3 x baseline?"}
    M -->|no| N2["no hit"]
    M -->|yes| HIT["hit: evidence = the day's txn ids"]
The day hash is keyed by transaction id, so a redelivered message overwrites its own entry instead of adding to the total.

ROUND_AMOUNT

Repeated round or just-below-threshold amounts (P11)

flowchart LR
    A["txn"] --> B{"amountInr >= minAmountInr?"}
    B -->|no| N["no hit"]
    B -->|yes| R{"original amount % 1000 == 0
or within 2% below CTR?"}
    R -->|no| N2["no hit"]
    R -->|yes| W["addAndGet aml:win:round:{acct}
window 10080 min"]
    W --> C{"count >= 5?"}
    C -->|yes| H["hit"]
    C -->|no| N3["no hit"]
Roundness uses the original currency: USD 6,000 is round even though its INR value is not.
