Detection pipeline

From an ActiveMQ message to scored, explained rule hits: idempotent, per account, and atomic with its database writes.

Step by step

  1. TransactionConsumer.consumeTransaction() is the only @JmsListener on sentinel.txn.ingested (concurrency 4–8). The JSON is converted to TransactionIngestedEvent by the shared converter.
  2. Inside one @Transactional: if processed_event already contains the transaction id, the message is a redelivery and is dropped.
  3. DetectionEngine.contextsFor() builds one TransactionContext per internal account: DEBIT for the source and CREDIT for the destination. Accounts with the prefix EXT- are not monitored.
  4. Every rule present in RuleCacheService.getActiveRules() runs for every context. A rule that throws is logged and skipped, so it cannot block the others.
  5. Hits are sorted by weight. RiskScoringServiceImpl computes min(100, (1 - prod(1 - w/100)) x 100 x m), where m comes from CustomerRiskLookup. The explanations are joined with " | ".
  6. For every account with hits, an AmlAlert row is saved and a RuleHitsDetectedEvent is sent to sentinel.detection.hits.
  7. The ProcessedEvent marker is saved in the same transaction; the timers sentinel_detection_latency and sentinel_ingest_to_detection_latency are recorded.
