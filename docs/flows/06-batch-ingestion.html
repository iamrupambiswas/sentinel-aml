Batch CSV ingestion

Bulk loading with Spring Batch: chunked, transactional, and with a line-numbered report for every rejected row.

Step by step

  1. BatchController.uploadBatch() rejects empty or non-.csv files.
  2. BatchIngestionServiceImpl.processBatchAsync() copies the upload to a temp file, inserts ingestion_batch with status PROCESSING and returns 202 immediately.
  3. The job is launched on batchTaskExecutor, a dedicated pool from AsyncConfig, so file processing cannot starve other async work.
  4. csvReader skips the header line but uses it in skippedLinesCallback to set the tokenizer's column names (BOM stripped). Strict mode turns a wrong column count into a FlatFileParseException.
  5. TransactionItemProcessor.process() checks required columns, parses the amount, currency and country code and the optional timestamp, then calls TransactionFactory.build() with externalRef = BATCH-{batchId}-L{line}.
  6. The writer persists each chunk's transactions and outbox rows in one transaction (chunk size 500, JDBC batch size 500).
  7. Skippable errors go to CsvSkipListener, which reads the batch id from StepSynchronizationManager and stores the line number, raw data and reason in its own transaction.
  8. BatchCompletionListener.afterJob() sums the read, skip and write counts and writes the final status, totals and completed_at. The temp file is deleted in finally.
  9. On application startup, BatchReconciliationListener marks any batch still in PROCESSING as FAILED, which covers a crash mid-batch.
