Gateway routing

The single entry point. It refuses oversized bodies (413), requests without a valid Keycloak JWT (401) and callers over their rate limit (429), then routes.

Service gateway-servicePort 8080Library spring-cloud-starter-gateway-mvc 4.1.9 (Spring Cloud 2023.0.6)

Step by step

  1. The client calls the gateway on port 8080. It is the only port external clients should use.
  2. RequestLoggingFilter logs ▶ [REQ] / ◀ [RES] / ✖ [ERR] and forwards an X-Trace-Id header (reused by every service's LoggingAspect, so one id follows the request across logs).
  3. RequestSizeLimitFilter refuses a body over 1 MB (50 MB for /api/v1/ingestion/batches) with 413: a declared Content-Length is checked up front, a chunked body is counted while it streams.
  4. SecurityConfig (Spring Security resource server) checks the Bearer JWT: signature against Keycloak's cached public keys, exp and iss. No or invalid token = 401. Roles are not checked here: each service does that (see Authentication & roles). /actuator/health/** stays open.
  5. RateLimitFilter takes one token from the caller's bucket in Redis (rl:sub:<JWT subject>, one Lua script: burst 100, refill 20/s). Empty bucket = 429 with Retry-After; every response carries X-RateLimit-Limit / X-RateLimit-Remaining. If Redis is down the request passes (fail open).
  6. Spring Cloud Gateway Server MVC evaluates the Path= predicates of each route in order.
  7. The first matching route forwards the request, unchanged (including the Authorization header), to its uri. The URI comes from an environment variable with a localhost default (12-factor).
  8. The downstream response (status, headers, body) is streamed back to the client.

Streaming responses

Server-Sent Events (/api/v1/alerts/stream) pass through because gateway MVC 4.1.6+ flushes text/event-stream responses after every chunk. Version 4.1.2 flushed only at the end, so an endless stream never left the gateway (ADR-007 D13).
